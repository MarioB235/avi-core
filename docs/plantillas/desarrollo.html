5 — Commit, push y PR vos autorizás

Skill: avicore-git-pr · auth: .cursor/README.md · plantilla PR completa en el skill

Ahora vamos a seguir el flujo Git para AviCore.

▶ Ejecutá pasos Git y PR completos sin parar a confirmar. Este mensaje autoriza commit, push y creación de PR. Si no hay cambios → informar y no commitear vacío.

Antes del commit (si hay código Laravel):
- php artisan test
- pnpm run build (si hubo front)

1. Verificar rama actual: git branch
2. Si estás en main: crear rama según tipo de cambio
   git checkout main
   git pull origin main
   git checkout -b [tipo]/[nombre]
   Tipos: feature/ fix/ refactor/ hotfix/ docs/ chore/
3. Si ya estás en rama existente pero el nombre no coincide con el tipo:
   Solo local: git branch -m [tipo]/[nombre-nuevo]
4. Si ya estás en rama correcta: continuar con esa rama

Verificar cambios: git status
Agregar cambios relevantes: git add .
Commit (Conventional Commits): tipo(scope): descripción breve
   Tipos: feat, fix, refactor, chore, docs, test, style
Push: git push -u origin [tipo]/[nombre]

PR: gh pr create o MCP user-github. Antes: gh auth status vs remoto (git remote get-url origin).

Base para redactar: chat completo (tabla 2, correcciones 3, docs 4) + diff actual.

Comandos locales — raíz del proyecto referencia, no mensaje

Ejecutá en la carpeta donde está artisan (PowerShell, CMD o bash). App en http://localhost:8000 (redirige a /login) — no abras :5173 en el navegador (es solo Vite). Fuente maestra: avicore-contexto/references/arranque-local.md. Git: vendor/, node_modules/, public/build/ y .vite/ no se suben al repo — si el IDE muestra miles de cambios, revisá que la carpeta abierta sea la raíz de AviCore (donde está artisan) y que no esté activado «mostrar ignorados» en control de código.

Qué querés hacer Comando Notas
