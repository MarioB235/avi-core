AviCore — 5 mensajes para copiar y pegar

Escribí /avicore-architect-direct, pegá el mensaje que corresponda y completá solo la parte final («Lo que necesito», archivos con @ruta, etc.). El agente elige el skill por vos.

Flujo de cierre recomendado: 2 (auditar, solo lectura) → 3 (corregir según tabla) → 4 (docs, skills y tooling) → 5 (PR con resúmenes del 3 y 4). Usá el 2–5 cuando quieras revisar calidad, corregir hallazgos, alinear docs o publicar en GitHub. Los acordeones de comandos locales y usuarios demo son solo consulta (no se pega al agente). Comandos detallados: docs/reference/arranque-local.md. Los mensajes 3 y 4 cierran con un resumen copiable de lo realizado — pegalo en el mensaje 5, sección «Resumen adicional», al abrir la PR. Catálogo skills y docs por mensaje: docs/cursor/03-skills-avicore.md. Las respuestas del agente van en prosa clara, no en informes con muchas listas.

3 — Corregir lo de la auditoría tests en verde · listo para PR

Skill: avicore-auditoria (aplicar) · usa la tabla del mensaje 2 en este chat. 

Según la auditoría de este chat, aplicá en AviCore las correcciones para subir el cumplimiento de cada fila auditada lo máximo posible según la tabla y sus brechas — no un parche mínimo.

Seguí /avicore-architect-direct y el skill avicore-auditoria (modo aplicar-correcciones). Corregí todas las dimensiones Parcial o No; implementá o ampliá tests cuando Tests lo requiera o la brecha lo pida (tests significativos, no triviales). Prioridad: bugs → seguridad → multiempresa → validaciones → tests críticos → UI/responsive.

Verificación obligatoria antes de cerrar: php artisan test (todo en verde; corregí fallos hasta pasar), npm run build si tocaste front o CSS, vendor/bin/pint si tocaste PHP. Sin commit, push ni PR — dejá todo listo para el mensaje 5.

Si alguna corrección altera contrato documental, anotarlo para el mensaje 4. Si el flujo aplicado difirió del skill, seguí docs/cursor/05-evolucion-skills-y-docs.md.

Al terminar, enviame un resumen breve y copiable: qué corregiste por archivo, % estimado tras corrección, verificaciones corridas (test/build) y pendientes. Lo pegaré en el mensaje 5, sección «Resumen adicional».

Comandos locales — raíz del proyecto referencia, no mensaje

Ejecutá en la carpeta donde está artisan (PowerShell, CMD o bash). App en http://localhost:8000 (redirige a /login) — no abras :5173 en el navegador (es solo Vite). Fuente maestra: docs/reference/arranque-local.md. Git: vendor/, node_modules/, public/build/ y .vite/ no se suben al repo — si el IDE muestra miles de cambios, revisá que la carpeta abierta sea la raíz de AviCore (donde está artisan) y que no esté activado «mostrar ignorados» en control de código.
